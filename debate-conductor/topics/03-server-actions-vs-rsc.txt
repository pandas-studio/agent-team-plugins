Next.js 15+ 기반 신규 SaaS 대시보드는 클라이언트 측 데이터 변형(mutation)을
모두 Server Actions 로 처리해야 한다 — 더 이상 별도 API route handler 를 두지 않는다.
RSC + Server Actions 만으로 mutation 까지 커버 가능한 시점이 왔으며,
route handler 는 외부 통합(웹훅·OAuth 콜백·third-party API)에만 한정한다.

이 stance 를 옹호하라. type safety, progressive enhancement,
DevTools 디버깅, 서버리스 cold-start 등 반론 축에 대해 구체적으로 답하라.

⚠️ 주의: 이 토픽은 Critic 이 OVERTURN verdict 를 자주 던진다 —
Server Actions 의 retry/optimistic UI 영역에서 약점이 명확하기 때문.
시연에서 OVERTURN 후 Round 3 generator 가 *다른 각도* 로 시작하는 것을 보여주고 싶을 때 사용.
