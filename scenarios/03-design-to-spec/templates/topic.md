# 보고서 생성 방식 결정

현재 __CURRENT_INTERFACE__는 보고서를 동기로 생성한다.

- 대안 A: 동기 처리를 유지하고 __SYNC_IMPROVEMENT__로 개선한다.
- 대안 B: 백그라운드 작업으로 전환하고 제출·상태 조회·결과 조회를 분리한다.
- 검토할 입장: 현재 제약에서는 A를 유지하는 편이 낫다. Generator는 이 입장을
  구체화하고 Critic은 B가 필요한 반례와 누락된 비용을 검토한다.

## 제공 사실

- 측정한 생성 지연과 측정 방법: __MEASURED_LATENCY__
- 예상 요청량과 동시 작업 수: __LOAD_AND_CONCURRENCY__
- 기존 호출자의 응답·호환성 요구: __CLIENT_CONTRACT__
- 운영 인력·배포·의존성 제한: __OPERATIONAL_CONSTRAINTS__
- 실패·중복 요청·재시작 시 요구: __FAILURE_REQUIREMENTS__

지연, 호환성, 운영 복잡도, 실패 복구, 테스트 가능성을 비교한다.
미측정 값은 사실처럼 사용하지 않는다. 추천 대안, 반대 근거, 추가 확인이 필요한
조건을 구분한다. 이 토론은 설계 근거를 제공하며 구현 승인이나 코드 변경은 하지 않는다.
